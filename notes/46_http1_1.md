# Introduction

HTTP/1.1 is one of the most important protocols used in web development.

Every time you:

* Open a website
* Call an API
* Load images
* Submit forms
* Download files

HTTP is working behind the scenes.

HTTP/1.1 became the standard protocol for communication between:

```text
Client ↔ Server
```

It powers most traditional web applications.

---

# What is HTTP/1.1

HTTP stands for:

```text
HyperText Transfer Protocol
```

HTTP/1.1 is:

* An application-layer protocol
* A request-response protocol
* Stateless by default
* Text-based
* Built on top of TCP

Introduced improvements over HTTP/1.0 such as:

* Persistent connections
* Better caching
* Host headers
* Chunked transfer encoding

---

# Why HTTP/1.1 is Needed

Modern web applications require:

* Reliable communication
* Fast resource loading
* Standardized APIs
* Browser-server communication
* Efficient networking

Without HTTP:

* Browsers could not communicate with servers
* APIs would not exist
* Websites could not function

HTTP/1.1 solved many performance issues of HTTP/1.0.

---

# How HTTP/1.1 Works

HTTP follows a:

```text
Request → Response
```

model.

Example:

```text
Client sends request
        ↓
Server processes request
        ↓
Server returns response
```

HTTP communication usually happens over:

```text
TCP/IP
```

---

# HTTP Request-Response Cycle

## Step 1 — Client Request

Browser sends request:

```http
GET /index.html HTTP/1.1
Host: example.com
```

---

## Step 2 — Server Processing

Server:

* Reads request
* Processes logic
* Accesses database if needed

---

## Step 3 — Server Response

Server returns:

```http
HTTP/1.1 200 OK
Content-Type: text/html
```

along with response body.

# HTTP Methods

HTTP methods define the action to perform.

| Method  | Purpose           |
| ------- | ----------------- |
| GET     | Retrieve data     |
| POST    | Send new data     |
| PUT     | Update data       |
| PATCH   | Partial update    |
| DELETE  | Remove data       |
| HEAD    | Get headers only  |
| OPTIONS | Supported methods |

# Persistent Connections

HTTP/1.1 introduced:

```text
Keep-Alive Connections
```

This allows multiple requests over the same TCP connection.

Benefits:

* Reduced latency
* Faster performance
* Fewer TCP handshakes

---

# Chunked Transfer Encoding

HTTP/1.1 supports sending data in chunks.

Example:

```http
Transfer-Encoding: chunked
```

Useful when:

* Response size is unknown
* Streaming data
* Large file transfers

---

# Caching in HTTP/1.1

Caching improves performance.

## Common Cache Headers

```http
Cache-Control: max-age=3600
ETag: "abc123"
```

Benefits:

* Faster websites
* Reduced server load
* Reduced bandwidth usage

---

# Cache Flow

```text
Browser Cache
      ↓
If Valid → Use Cached Data
      ↓
Else → Request Server
```

# Cookies and Sessions

HTTP is stateless.

This means:

```text
Each request is independent
```

Cookies help maintain sessions.

## Example

```http
Set-Cookie: sessionId=abc123
```

Common uses:

* Authentication
* User sessions
* Preferences

# Content Negotiation

Clients can request different formats.

Example:

```http

```

* JSON
* HTML

* Images

---

# HTTP/1.1 Limitations

Although powerful, HTTP/1.1 has limitations.

## Head-of-Line Blocking

Only one request processed at a time per connection.

---

## Multiple Connections

Browsers open many TCP connections to improve speed.

This increases:

* Network overhead
* Server load

---

## Large Headers

Headers are sent repeatedly.

This wastes bandwidth.

---

# HTTP/1.1 vs HTTP/1.0

| Feature                | HTTP/1.0 | HTTP/1.1 |
| ---------------------- | -------- | -------- |
| Persistent Connections | No       | Yes      |
| Host Header            | Optional | Required |
| Caching                | Basic    | Improved |
| Performance            | Slower   | Faster   |
| Chunked Encoding       | No       | Yes      |

---

# HTTP/1.1 vs HTTP/2

| Feature            | HTTP/1.1 | HTTP/2 |
| ------------------ | -------- | ------ |
| Data Format        | Text     | Binary |
| Multiplexing       | No       | Yes    |
| Header Compression | No       | Yes    |
| Performance        | Slower   | Faster |
| Single Connection  | Limited  | Better |

---

# HTTP/1.1 in Node.js

Node.js provides built-in HTTP support.

## Example

```javascript
import http from "http";

const server = http.createServer((req, res) => {
  res.writeHead(200, {
    "Content-Type": "text/plain"
  });

  res.end("Hello World");
});

server.listen(3000);
```

# Interview Questions

## Q: What is HTTP/1.1?

A protocol used for communication between clients and servers on the web.

---

## Q: Why is HTTP/1.1 stateless?

Because each request is independent and the server does not automatically remember previous requests.

---

## Q: Difference between GET and POST?

* GET retrieves data
* POST sends data to server

---

## Q: What are HTTP status codes?

Codes returned by the server indicating request result.

---

## Q: What is Keep-Alive in HTTP/1.1?

A feature allowing multiple requests over a single TCP connection.

---

## Q: What is caching in HTTP?

Storing responses temporarily to improve performance and reduce server load.

---

## Q: Why is HTTPS important?

Because it encrypts communication and improves security.

It enables:

* Websites

HTTP/1.1 introduced major improvements like:

* Persistent connections
* Better caching
* Host headers
* Chunked transfer encoding

Even though newer versions like HTTP/2 and HTTP/3 exist, HTTP/1.1 is still widely used across the internet.

Understanding HTTP/1.1 is essential for:

* Backend developers
* Frontend developers
* Full-stack engineers
* DevOps engineers
* API developers

Modern web architecture heavily depends on HTTP-based communication.
